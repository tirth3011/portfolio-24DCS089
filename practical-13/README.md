## 🛡️ Responsible AI Principles Applied

1. **Strict Server-Side Key Isolation**:
   - The AI API key (`GEMINI_API_KEY` / `OPENAI_API_KEY`) is stored strictly in backend `.env`. It is never bundled into client JavaScript or visible in browser network DevTools.
2. **Data Privacy & PII Scrubbing**:
   - Prompts are cleansed via regex tokenization before reaching external models, redacting email addresses, passwords, tokens, and credit card numbers.
3. **Graceful Degradation Safeguard**:
   - If the AI API returns a 401 Unauthorized, rate-limit error, or times out, the backend catches the exception without crashing and supplies context-aware heuristic suggestions.
4. **Human-in-the-Loop Review**:
   - AI outputs are rendered inside an editable draft drawer. The user maintains final control to modify, accept, or discard the suggestion.
5. **Visible AI Disclaimer**:
   - Every AI-generated output displays a mandatory notice informing the user that the content was generated by an AI assistant and should be independently reviewed.

## 💡 Key Conceptual Analysis

### 1. Why must the AI API key be called from the backend rather than directly from the React frontend?
Any secret key embedded in React code is exposed to the public:
- Frontend code is sent directly to the client browser and can be extracted via `View Page Source` or client bundle inspection.
- Direct API calls reveal the `Bearer <token>` in the browser DevTools Network tab.
- Attackers can steal the key and incur thousands of dollars in unauthorized usage.
- Proxying through an Express backend keeps credentials strictly on the server and allows you to enforce rate-limiting, authentication, and logging.

### 2. What does 'graceful degradation' mean in this context, and why does it matter for third-party dependencies?
Graceful degradation is the design practice that enables a system to continue operating at a reduced or fallback level of functionality rather than failing completely when a component or third-party service is unavailable. Because cloud AI APIs are outside our infrastructure control (subject to outages, rate limits, quota exhaustion, and network latency), wrapping the call in error handling and providing heuristic fallbacks ensures users can still create and manage tasks without the application crashing.

### 3. Privacy and governance implications of sending task data to an external AI API:
- Sending proprietary company data, customer PII, trade secrets, or unhashed credentials to external commercial LLMs risks data leaks, non-compliance with privacy regulations (GDPR, CCPA), and intellectual property exposure.
- **Sensitive data that should NEVER be sent**: passwords, private encryption keys, personal identity numbers, financial records, medical information, and internal confidential IP.
